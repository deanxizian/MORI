# ADR-SW12-001：V1.2 软件迁移与物理门控

日期 2026-09-22；状态：DOCUMENT / PASS（软件决策已落地），BENCH/ROBOT / NOT_TESTED。

用户要求更新 V1.2，附件作为具体实施依据；用户此前明确仅网页优先于附件 App 条目。没有生成新任务或代理。新规范在根目录原文保存，原 V1 和 A0 软件、数据与报告保留。读取时硬件仍为旧 H0.3，工作期间并行任务更新 H0.1/M1；本记录按新的 **V1.2-H0.1 / V1.2-M1** 接口复核，不再把已解决的旧 CRC16/尺寸冲突列成当前问题。

1. `firmware/motion` 默认 CMake STM32F413，原 ESP32 入口由 MORI_LEGACY_ESP32 显式选择，同一工作区，不复制第二份正式固件。Arm 14.2.Rel1（实际 gcc14.2.1）；CMSIS/HAL 具体 commit 见锁文件。默认物理功率/平衡开关 OFF；打开时报未释放板端口错误，不设“已确认”。编译镜像仅禁驱启动，无 GPIO/电机外设初始化。控制核心可注入传感器和时钟，协议解析独立于 HAL。
2. S288 收包取官方 C 定义的 26 字节显式布局。`protocol.md` 的 vol=uint16 与 C 的 uint8 不一致；Python 示例对 sensor/vol 用 signed byte、负位置 pack 为无符号 I、round 与 C 截断不同。没有真实报文，官方 C 差分测试仅 HOST_TEST。输出扭矩值为协议估计值，不是负载传感器。raw 编码范围远大于物理允许值，**不可用编码范围设置出力**。模式0、零扭矩、Kp/Kd0、timeout 各自真实行为均待测；故障请求外部禁驱，不宣称发 mode0 可自由卸力。
3. 3S4.2V/cell 满充假设12.6V等于 S288输入上限，无回灌余量。旧2S6.8/6.6/6.0V、1.3A、20kHzPWM、PCNT CPR均只属旧profile。新软件阈值 null、物理扭矩上限0、全部增益0，电池/驱动安全链未核验不能ARM。
4. 运动高层仍m/s/rad；公共轮扭矩仅由姿态反馈产生，速度误差只产生有限倾角参考；差动只使用剩余扭矩。导航目标限加速度，纠偏输出不加全局慢斜率。常量不从Hover tor/原增益迁移。台架前无调好参数；测试里的 Nm 上限/增益是 ASSUMED 夹具。
5. SCS独立总线，原厂SCSCL大端/位置1024计数参考；不默认断扭矩；头测量失效停止跟随并保持健康本地平衡。联合范围由机械签字的 region 回调提供，测试菱形只是夹具，两个单轴角度范围不等于联合包络。
6. 微雪示例使用IDF5.5.1与camera>=2.1.4。保留已安装并重新编译成功的IDF5.5.2，camera由2.0.16锁到2.1.4；新增codec1.5.4、ST77916 1.0.1、CH32 1.0.1。升级前锁文件保存到reports/v1_2。没有导入另一个完整应用主循环；LVGL9.2.2维持。40ms只是25fps调度请求，实机帧率无数据。
7. 电气契约的CAM L3 18P / LCD35079针号对照已存在，但FFC接触面/针距/16–18脚仍未释放；CAM侧TE脚NC，不能承诺TE同步。音频参考为ES8311到ES7210的模拟参考，PCM槽/延迟未知，不能把软件 MR 队列当此板AEC已接通。CAM BAT不接3S；板上CH32只作I/O扩展。
8. MORI/2不升不兼容大版本；状态增加版本、测量valid/null字段。实机配置一律不由网页或模型写寄存器/原始扭矩。板间速率由硬件填写，6Mbps只属于S288总线；协议CRC不代替WSS身份认证。

需要硬件决定：F413实际板/USART+DMA/SPI/DRDY/时钟与容差、收发器TX释放和断电耐受、安全禁驱端口、S288 ID/符号/物理限幅/回灌、SCS标定/联合区域、相机内外参及头反馈时序、屏FPC/初始化序列、音频槽/采样率/参考对齐、功能按钮和电池/温度/电流测量路径。所有请求见 ICR-019～022，未改写硬件真源。
