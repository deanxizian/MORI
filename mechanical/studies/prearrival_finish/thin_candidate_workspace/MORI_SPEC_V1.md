MORI V1 — 统一产品与工程规格

版本：1.0｜整理日期：2026-09-21

本文件冻结产品方向，不表示硬件、成本、续航、闭环控制或安全性已经通过实测。
本规格取代此前提示词中的“三电机、单轴头部、无摄像头、纯手动、浅色背景”等旧约束。

1. 用户已经决定的内容

项目

冻结要求

名称与用途

MORI；个人自用，准备开源，保留以后产品化销售的可能

一次性预算

首台原型材料与基础打样合计不超过人民币 1000 元

预算口径

含四个执行器、驱动、主控、屏幕、摄像头、音频、电池与电源、PCB 基础打样、打印材料、连接器线束及运费；工具设备、已有腾讯云资源与按量云 API 费用单列。不得靠漏项“达标”

尺寸

正常装配姿态总高不超过 300 mm；先以约 250–280 mm 布局，不要求做满 300 mm；报告完整运动包络

外观

极简；头部正球形母体；身体为更大正球形母体，顶部与左右轮位局部截切；无明显脖子；腹部离地；轮壳有真实间隙

配色

哑光暖白壳体、黑/深灰轮胎、纯色轮毂；不要黄色条、嘴、耳朵、天线、翅膀、装饰图案

显示

圆形屏幕，纯黑背景，只保留 Grok Bot / bloub 风格双眼；不显示完整黑色角色轮廓、轨道、粒子或白色背景

执行器

共 4 个：左右轮电机 2 个，头部 yaw/pitch 舵机 2 个；无第三机械歪头轴

底盘

纯两轮主动自平衡，参考 RIG-Hover；无运行时第三支撑轮、万向球、滑块、触地支脚

头部

左右转与抬头低头，参考 StackChan；角度范围由机构与负载决定

场地

V1 仅平整、坚硬的室内地面；不要求桌面自由行驶、门槛、楼梯、地毯与室外

移动能力

指令移动、主动短距离活动、跟随、巡游全部纳入开发；按分级测试逐项启用，不把未完成模式包装成已支持

摄像头

必须安装；支持关闭、按需拍照/识物、持续目标跟踪三种模式；“支持 A/B/C”解释为运行模式切换，不是删掉摄像头

保护传感器

本版不增加专用测距、避障、防跌落等移动保护传感器；平衡 IMU、编码器、电源监测不属于此项删除范围

语音

中文优先、唤醒词优先，至少 1 个实体功能按钮；音色与性格没有指定，采用自然普通话、中性友好风格，可配置

后端

已有腾讯云服务器；配置、地域、系统、GPU、带宽与当前负载未知，不能假设可直接运行大模型或高帧率视觉

模型路线

暂不接 Grok 原生语音；ASR / LLM / TTS / 视觉服务可更换，默认通过适配器调用服务

记忆

必须有跨重启、跨会话的长期记忆；可查看、纠正、删除、关闭

续航

至少 60 分钟目标；以通电主动平衡、摄像头跟踪、表情及间断语音的定义工况测试，不用断电托架待机替代

充电

V1 USB-C 有线充电；未来触点回充仅预留接口，不实现自动回充，不增加自动找座硬件

客户端

网页 + 手机 App + 语音 + 实体操作；PWA 不单独充当原生 App 交付

2. 本轮采用的工程默认值（可由验证结果调整，但不得违反上表）

头部初始范围：yaw ±60°，pitch 向上 25°、向下 20°；不追求无限旋转。

结构初值：头母球 105 mm、身体母球 150 mm、轮径 95 mm、轮宽 18 mm、腹部离地 25 mm、轮壳目标间隙 4 mm、壳厚 2.4 mm。都是试算输入，不是已适配器件尺寸。

默认独立运动控制域与交互控制域。硬件按低成本双 MCU 预留安装与预算：交互 MCU 优先 ESP32-S3，运动 MCU 优先同工具链的 ESP32-S3 小模块；是否改成其他 MCU 由硬件 ADR 说明。这里不是增加电机，也不是自动达到功能安全等级。

不新增树莓派、Jetson、激光雷达等昂贵板卡。不因算力不足悄悄加入第三主控。

运动 MCU：身体 IMU、两轮反馈、平衡控制、四执行器的有界目标执行、状态机、硬件故障与心跳处理。

交互 MCU：圆屏双眼、摄像头、麦克风、扬声器、唤醒、联网、视觉处理候选及工具网关。运动安全判断最终在本机执行。

双 MCU 采用有帧界定、长度、版本、CRC、序号、心跳、时效与重启会话标识的本地串口接口；速率与引脚由硬件冻结，不能用不受约束字符串控制电机。

软件：运动参考 Hover；头部参考 StackChan；表情移植 bloub 眼睛逻辑并由 LVGL 输出；交互参考小智 + ESP-SR；腾讯云使用小智兼容后端的最小部署，增加长期记忆与设备控制服务。

网页/手机共用 Vue 3 + TypeScript + Vite 界面与协议，手机用 Capacitor 生成 iOS/Android 工程。先做控制台与原生壳的实用功能，不做商城、账号社交、支付和 App 商店提交。

品牌名 MORI；期望唤醒短语“你好，Mori”（中文读音“你好，莫里”），作为暂定可配置目标。必须核验对应离线模型、许可及训练/定制成本；不能把字符串配置当成唤醒模型。按钮/已有测试词可用于开发，但不能宣称最终自定义词已交付。

长期记忆默认保存经确认的事实、偏好和必要会话摘要；每条带来源、时间、类型及置信标记。推断不能冒充用户事实。敏感信息与身份模板不自动长期保存。

原始音频、连续视频默认不长期保存；用户明确拍照的文件与临时识图上传分别处理，并提供删除与留存设置。

手机与网页共用设备配对、身份认证和命令仲裁。配网与首次绑定需要物理接触/一次性凭证，不能任何局域网设备均可控制。

普通短按触发/打断对话；双击取消移动目标并继续平衡。长按复位、配网重置、刷机只在可靠外部支撑的维护态操作，不能平衡中清 NVS 或自动重启。

底部允许一个低调物理电源开关及隐藏调试接口。严重故障禁驱可能导致倒下，需要单独说明，与正常停止不同。

提供无电机、无充电触点的外置打印停放托架，用于有线充电、刷机和关机；不属于机器人运行时第三支撑。首版禁止插线自由移动。

3. 自主行为的能力边界

所有模式都要进入设计、界面、协议和测试，不把它们默默移到“以后再说”。但是，未验证时默认不解锁相应实机模式。

手动/语音：低速有界前后、转向、停下、头部看向。

主动短距离活动：由本地行为状态机在有限区域提出短动作，受本地限幅与操作者授权控制。

跟随：目标由用户选择/确认；先头部跟踪，再验证慢速底盘跟随；多人交叉或目标丢失时不擅自换人，不承诺跨房间重新识别主人。

巡游：清场区域中的有限里程/时间序列或经验证的示教路线。编码器里程计会漂移，不能将其虚拟围栏描述为可靠的物理防跌落边界。不承诺任意户型自主导航。

不安装专用保护传感器，因此不能宣称具备可靠避障、防跌落、复杂家庭环境无人值守巡航。V1 自主模式只在人工看护、无台阶、无障碍、无宠物儿童进入的受控地面测试。

初始自主测试目标限速 0.10 m/s，单段目标位移不超过 0.30 m；这是保守调试起点，不是安全认证。不得把平衡恢复所需执行器输出也按上层巡航限速简单切断。

本地命令租约初值 300 ms；跟随观测最大允许年龄初值 250 ms。两者须结合测试调整，不能越慢的感知越无限放宽；远程通信超时必须终止主动位移目标。

有效命令/目标/视频丢失时，在健康控制前提下减速到零并继续平衡；倾倒、过流、IMU失效等严重故障按本机故障策略禁驱并锁定，不用“继续平衡”掩盖不可控状态。

摄像头不等于距离传感器，不把画面中人的大小直接当精确距离。需标定、观测置信度和相机随头部转动的坐标变换。

平衡和高速运动反馈不能依赖腾讯云。视觉跟踪优先评估设备端轻量实现，云端用于按需语义识物和会话。无法满足时延时，先允许站立/托架跟踪，不得启用有陈旧观察的实机跟随。

5. 功耗与续航验收

先以实测平均功率计算电池 Wh，再选容量与串数，保留能量余量。1小时是目标，不是已验证结果。
例：假设平均8W、可用能量按标称的80%估计，则1小时需要约10Wh标称能量；这是计算示例，不是整机实测。不能据此锁定电池。
建议建立60分钟混合工况：持续主动平衡与圆屏，摄像头轻量跟踪开启；累计10分钟低速移动；累计10分钟语音交互；每分钟一次小幅头部动作。记录屏幕亮度、音量、实际移动比例、电池温度、平均/峰值电流及剩余能量。
缺少保护传感器时，此测试在安全清场环境下进行。托架待机续航另外测，不可抵替。

6. 共享接口、坐标和状态

机械建模参数用 mm，固件控制采用 SI：m、s、rad；界面显示 deg 可以，但必须显式转换。

世界/机身建模初始方向：X向右、Y向前、Z向上，右手坐标系。轮轴沿X；头 yaw 正方向向左，pitch 正方向抬头。身体前倾角的正方向由控制契约独立明确，不能与头pitch或IMU原轴混用。

所有位置、速度、角度必须带坐标系与时间戳。左右轮物理电机方向可以不同，但逻辑“正轮速”统一为向前滚动。

平衡 IMU 固定身体刚性框架，不跟随头转。摄像头位于头部，需要内参、安装外参与头部角度变换；无头部实测反馈时必须标记角度为估计。

STOP_MOTION：撤销移动目标，健康时继续平衡。DISARM/FAULT_STOP：禁驱，可能倒下。两者在所有客户端、语音工具与固件中不得混名。

状态至少含 BOOT、SELF_TEST、DISARMED、ARMED_IDLE、MOVING、AUTONOMY、DOCKED_MAINTENANCE、FAULT；对话状态另设，不能拿“sleep表情”控制驱动。

命令必须有device_id、session_id、command_id、source、type、参数、时效和权限；结果区分 ACCEPTED / RUNNING / COMPLETED / REJECTED / EXPIRED / CANCELLED / FAULT。

实时层不运行 MCP、LLM 或摄像头语义推理。交互层接受MCP/函数调用后转成受限内部命令。

7. 交付目录和顺序

建议一个仓库，分支/worktree分工：

MORI_SPEC_V1.md
AGENTS.md
contracts/                # 协议schema、坐标、机械接口、器件包络
config/                   # geometry、capabilities、limits、power profiles
mechanical/               # bpy脚本、blend、零件导出、图纸、托架
hardware/                 # BOM、选型、原理图、PCB、测试点、电源树
firmware/motion/          # 运动MCU
firmware/interaction/     # 交互MCU
backend/                  # 设备连接、语音适配、记忆、配置
apps/console/             # 共用网页界面
apps/mobile/              # Capacitor iOS/Android
simulation/               # 动力学与设备模拟器
reports/                  # 检查、测量、证据、成本与风险
refs/                     # 锁定版本的参考资料，不盲目复制运行环境

顺序：机械参数化布局 → 硬件关键器件包络/预算确认 → 回写机械并冻结接口 → 原理图/PCB设计 → 模块上电与控制验证 → 带头部/表情/音频集成 → 摄像头与记忆/客户端 → 跟随/巡游受控测试。
软件模拟器、协议、表情与客户端可提前并行。模型不能在不知道器件时冻结加工孔位；原理图可先设计但未实测版本不能标为生产验证完成。
