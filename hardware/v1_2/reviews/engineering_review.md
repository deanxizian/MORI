# MORI V1.2-H0.2-P1 工程审查

2026-09-22。原型包含运动载板、身体IMU板、电源调理板三套**原生 KiCad 原理图与已布线 PCB**。实际 KiCad10.0.6 ERC/DRC、未连接及原理图一致性检查分别为0。它们仍为 **PROTOTYPE / 未台架验证 / 不可直接下单**。电源板不是充电器，电池/充电模块、若干采购料号、整机装配和6Mbps实物物理层尚未闭合。

> **S3更新（2026-09-22）**：当前两路5V已改为电源板上的TPS54302原理图，见[新审查/接线/计算](../schematic_S3/README.md)。本文件其余P1/P2布局描述是历史依据；S3没有更新PCB或冻结板框，原板不能直接实施新增电路。

## 1. 已落实的主路线

S288×2、SCS0009×2、微雪33700 OV3660、微雪35079保持不变。运动原型采用WeAct **STM32F412RET6 64Pin V1.1** 适配，理由与影响见ADR-HW-V1_2-002；这不是F411 BlackPill，不能按其排针接线。ICM-42688-P采用可审查的独立20×16mm小板，LGA需SMT装配服务；报价需包含贴装，用户目前只有万用表和限流电源。

外置稳压工程参考仍为Pololu D36V50F9#4094（9V）与D24V22F6#2859（6V）。[9V原厂](https://www.pololu.com/product/4094)、[6V原厂](https://www.pololu.com/product/2859)提供尺寸及工作范围，国内所选SKU/价格/温升仍待核。原D24V22F5#2858×2已由S3板载TPS54302电路替换；其模块尺寸、重量和报价不再用于新设计。预算不得用美元换算充当国内报价。

原生工程目录：`kicad/MORI_motion_P1`、`kicad/MORI_imu_P1`、`kicad/MORI_power_P1`。工程自带符号、局部封装库、完整网络、BOM、生成源及本地路由日志。`previews/`是原生CAD导出预览；`mechanical/`的STEP明确只含裸板，不含未核实的整套堆叠高度。

## 2. 时钟、DMA、物理链路

WeAct图中8MHz HSE；拟采用M=8、N=192、P=2、Q=4，得到SYSCLK/AHB/APB2=96MHz、APB1=48MHz、USB48MHz。VOS=11，3.3V时Flash3WS，来自RM0402表6。USART1 OVER16、BRR16名义6Mbps；USART2 BRR48及USART6 BRR96均为1Mbps。算术误差0不包括晶振随温漂、接收端误差及信号完整性，也不代表固件已实施。

| 用途 | MCU信号 | DMA分配（RM0402表30/31，p199） |
|---|---|---|
| S288 | PA9 TX、PA10 RX，AF7，USART1 | TX DMA2 S7 C4；RX DMA2 S2 C4 |
| SCS0009 | PA2 TX、PA3 RX，AF7，USART2 | TX DMA1 S6 C4；RX DMA1 S5 C4 |
| CAM板间链路 | PC6 TX、PC7 RX，AF8，USART6 | TX DMA2 S6 C5；RX DMA2 S1 C5 |
| IMU SPI1 | PA5 SCK、PA6 MISO、PA7 MOSI，AF5 | RX DMA2 S0 C3；TX DMA2 S3 C3 |
| IMU片选/中断 | PA4 GPIO CS、PB0 EXTI0 | 定时器自由运行时间戳；不占上述DMA |
| 电源采样 | PC0/1/2 ADC1通道10/11/12 | 首版定时低优先级采样；如DMA，保留DMA2 S4 C0 |
| 调试 | PA13 SWDIO、PA14 SWCLK、NRST | 保留SWD；PB3用于FAULT时需关闭JTAG复用 |

板上的PB11在F412配置为VCAP相关位置，**不作GPIO**。USB PA11/12保持维护用途；模块TF相关引脚不挪作新功能。USART6占PC6/7；不能同时启用与其冲突的外设。各UART/SPI拥有独立DMA stream，并非只是channel号不同。

S288与SCS采用各自的SN74LVC2G125；接收器常开，发送端独立三态并经68Ω阻尼。默认OE上拉；SN74LVC2G32将未ARM状态并入两路OE。器件Ioff及输入容限不证明执行器的VIH/VOH已经匹配：3.3V发送是否可靠、总线空闲电压和5.5V输入上限仍需实证。不能把双推挽直接短接。首轮数据信号与地成对，短主干、短分支，建议总线≤150mm、支路≤10mm作为试验起点；这是布线目标，不是保证的最大线长。

发送后等**USART TC**再释放OE，不能用DMA完成代替最后停止位发完；本机echo剔除，RX DMA有固定长度/超时/错误恢复。两轮顺次20B请求+26B反馈的理想线速153.33µs。建议每轮回包窗口先限400µs、单周期不重试，500Hz候选周期中为两轮预留约0.9ms；实际回包时延/控制抖动不达标则停止解锁，不能无限延时等待。

宇树C/Python协议审计保留：258组CRC以及6个坏帧反例在HOST通过；Python负角度打包、有符号uint8和舍入差异已复现。`s288_reference_audit.json`中的FAIL描述供应商示例差异，不应删掉。转子/输出端单位和目标固件仍需抓包；任何协议字段整数均不得直接称SI牛·米。

板间链路使用TXU0202，运动3.3V为VCCA、CAM J11.3自身3.3V为VCCB，实现掉电侧隔离。两路稳压输出不相连；信号地相连。MORI/2沿用软件已有`contracts/wire.*`，1Mbps8N1、158B帧上限、CRC/session/sequence/租约；坏包、UART0启动日志、缓冲堵塞均不能延长命令租约。CAM重启使位移命令失效，运动域在自身健康时继续平衡；共享电池跌落仍可能令两域同时失效。

## 3. 禁驱与电源原理

运动载板U5为SN74LVC1G74，D/PRE固定高。只有PB7新的ARM上升沿才能置位；PB8仅以开漏拉低CLR，禁止推挽拉高。J8是常闭维持接点：断开、拔线均经下拉清除锁存。TLV803EA29在3.3V不足时清除，NRST、FAULT_N、CHG_N通过肖特基清除。复位/故障解除后仍需重新ARM，不能自动恢复。物理禁驱会失去平衡扭矩，需要托架/外部保护；普通PC13用户按钮不直接复位MCU。固件必须另外启用IWDG，这颗电压监控器不是软件看门狗。

电池经外部6.3A保险、具备相应DC额定的总开关，到电源板J1。Q1作反接保护、10mΩ分流器监测放电；INA180A1增益20，输出约0.2V/A。它不是双向电量计，不能宣称测到充电电流。PC0/PC1使用100k/27k分压，12.6V对应2.679V；电压准确度需VREFINT/电阻校准。掉电时每个分压通道的注入电流上界约126µA，3.3V关断/棕断与锁存行为列入实测，不用弱反灌支撑逻辑运行。

轮部9V、头部6V分别经B540C反向隔离与ARM控制的PMOS，后端各1000µF/16V电解。电源回灌不进入非吸能型稳压模块。肖特基产生压降和热：按模块±4%及二极管0.2–0.55V假设，轮端约8.09–9.16V，头端约5.21–6.04V；并非始终6V/9V。SCS保守按原厂4.8V额定0.65kg·cm计算。

每个执行器母线有由本母线供电的LM393B+TL431B比较器及AO3400A吸能开关，外接脉冲额定功率电阻。它在运动3.3V消失时仍能由回灌能量供电。轮部静态开启范围10.71–11.00V、OV故障11.67–11.98V；头部开启6.56–6.74V、OV故障7.07–7.25V。此为元件容差计算，不是动态钳位保证；上电共模范围、门极延迟、导线电感、温升均未实测。过压故障切断供能也会造成跌落。

最重情景的保守回灌设计脉冲约0.8J；1000µF从9.5升到10.8V只吸收0.013J。轮部5.6Ω在10.8V约20.8W，必须核实电阻脉冲曲线/温升；**标5W的电阻不因此自动合格**。普通限流电源通常不能吸收回灌，不可把它当电子负载。P1外置电阻与线束的寄生电感使示波器验证不可省略。

运动与CAM使用两路独立5V稳压，输入支路保险/线束应按所选模块和负载配置；不把马达电流穿过开发板/FFC/USB。共享电池、总保险和地仍是共因故障。板上信号与功率返回经宽地铜相连；ADC输入Kelvin支路单独从分流器附近取样，布线复核不等于校准。

USB-C 3S充电模块尚未冻结。IP2326原厂资料明确可选3S充电、但内置均衡只有2S；不能买常见板就称已有3S均衡/电源路径。匹配的成品包必须提供独立保护、均衡、NTC和允许充电条件。P1只实现VBUS检测/充电禁驱输入，**未实现USB-C CC、PD协商或CC/CV充电**。未选模块时普通5V的充电行为不能保证，禁止连接电池验证。充电维护中机器人在托架、禁驱，暂不允许边充边正常运行。

CAM的BAT单节接口空置。检修电脑USB时先托架、禁驱并拔掉机器人给CAM的5V电源线，再接电脑；运动板SWD不从调试器额外供电。此版本用明确的互斥维护流程避免两电源相连，未宣称有自动电源MUX。一个外部充电口不自动承担两个MCU下载。

调试：WeAct P5顶面，1GND、2GND、3PA10、4SWCLK、5PA9、6SWDIO、7NRST、8VTref3V3；载板仅E7采NRST，不把其余调试孔接成运行UART。需要ST-Link兼容调试器（未拥有，另列工具成本），初期不用买S288 USB转换器来充当运动主控。

## 5. 布局、质量与控制裕量

运动70×35mm/IMU20×16mm的板框与原预留二维一致，但板底连接器、实际堆叠和拔插空间尚不保证。电源80×45mm加最高16mm电解、外置稳压模块及电阻，**不符合44×16×10mm预留**；必须由机械任务重排，不缩小元件、不覆盖机械契约。`handoff/mechanical_P1.json`给出孔位、连接器位置、原生裸板STEP。

运动/IMU两层1oz、0.15mm净距与0.2mm信号线；电源两层2oz候选、主要电流网络1mm（实际必要颈缩/引脚更窄，不能单凭netclass担保额定）、0.2mm净距、双面地铜。IPC-2221关系只作为估算，实际铜厚/散热/电流路径/过孔并联/焊接热需检查。电源拓扑不含自研高频降压回路，开关回路由外置成熟模块承担。板上比较器、电源输出、吸能回路仍有动态验证要求。

CAM天线必须按实际板修订核实位置，15mm周边无金属/无电池可作初始净空请求，不能假装已具备Wi-Fi厂商认证。运动板无RF。身体IMU固定于刚性框架，远离线束牵拉和马达振动，芯片轴向到机身坐标必须登记；禁止以头部IMU替代关节变换。

动力脚本读取最新机械质量、原始惯量、头部组合姿态；分开轮系/机身，并包含延迟、饱和、反向损失假设。56个条件试验只说明“若电机能提供所假设力矩”的模型响应。S288连续扭矩未知，0.6N·m不能保证其够用。轮径95mm时0.1/0.3/0.5m/s对应约20.1/60.3/100.5rpm；输出8192状态/转不是AB×4。

头部将重力矩投影到随yaw旋转的真实pitch轴，再加惯量×角加速度和线缆/摩擦。SCS有位置回读，但舵机轴角不等于无回差的头部光轴；视觉外参要含传动、机械零点与反馈时间戳。轮轴29mm悬臂、6mm轴承间距使外轴承反力放大，具体值见计算报告；轴承型号/钢材/打印支承不确认前不得宣称承载通过。

续航以Wh计算：3S2200/2600mAh在80%可用能量及15%余量假设下，60分钟允许平均电池功率约16.6/19.6W。容量、寿命、低压提前托架与转换效率仍是假设；18W平均时2200mAh估算约55分钟，不能保证一小时。按V1.2混合工况做完整验收。

## 6. 显示、视觉、音频与唤醒

LCD35079官方Rev1 STEP已由机械任务1:1导入：有效直径45.68mm、玻璃55mm、总深度CAD9.35mm，PDF9.1为参考且孔中心约0.06mm差异。68mm黑面罩不是68mm发光屏。CAM板框现已核为37×37mm、孔中心32.6mm方阵；最高件/插头深度和质量仍未知。完整来源与冲突沿用机械记录。

18P FFC主体信号逐针表已给出。LCD官方配件为0.5mm18P200mm同面线；CAM两端接触面和16–18脚仍待确认，TE在CAM端未接。不要为消除未知而凭空加无用转接板：原生屏幕转接PCB仅在确定线序/朝向不匹配后才需要。

OV3660驱动列出2048×1536上限与压缩/RGB输出；采用传感器JPEG用于拍照，持续观察先从320×240、目标10fps试起。ESP32-S3的DVP、QSPI屏、I2S外设可以分配，PSRAM/GDMA/CPU仍共享；必须记录并发P95/P99时延、丢帧与buffer水位，**10fps不是实测性能**。官方驱动提醒RGB/YUV与Wi-Fi会增加丢帧风险，JPEG双缓冲和转换也消耗内存与时间。[驱动原文](https://github.com/espressif/esp32-camera)

360²RGB565单帧259200B、双帧518400B；40MHz四线SPI理想20MB/s，完整刷新理论12.96ms，不计命令/空白/仲裁。黑底双眼应优先局部刷新。QVGA RGB565双帧307200B，RGB888单帧230400B；模型工作区、PSRAM DMA限制、音频环形缓冲须另外计入，不能只见8MB便判并发通过。

ESP-WHO现在包含人脸和行人检测示例，基于ESP-DL，支持ESP32-S3；微雪33700不是自动匹配的官方BSP。人脸检测/行人框并不提供稳定目标身份或避障。模型、跟踪关联与云请求应分层：相机观察年龄超过规格起点250ms时撤销跟随位移，运动域仍正常平衡；不能默认无上限云依赖。[ESP-WHO](https://github.com/espressif/esp-who)

微雪已有双麦、ES7210、ES8311与NS4150B。ES8311模拟播放参考经原图AEC网络进入ES7210 MIC3；按16kHz PCM起步，实际TDM槽位、通道顺序、幅度和参考延迟必须标定。该参考位于功放前，不能反映扬声器非线性。BTL扬声器两线都不接GND；保持独立音腔、麦克风声道与隔振，记录电机持续纠偏噪声。无需重复加麦或codec来增加成本。
