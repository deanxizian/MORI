请为我的 DIY 陪伴机器人 MORI，建立一个可编辑、可重复生成、能够检查尺寸的 Blender 三维项目。

目标是把外观概念推进到装配与结构预研模型，供后续硬件选型、3D 打印打样使用，而不是再生成一张看起来合理的产品海报。

使用 Blender + Python（bpy），优先通过本地 Blender 命令行执行。已有可用的 Blender MCP 时可以用于查看和交互修改，但不要把 MCP 当作开工前提。

先检查当前目录、已有文件和 Blender 环境，不要删除或覆盖无关文件。简要说明计划后直接实施，不要只输出教程。

硬件型号尚未明确的部分，用有尺寸、明确标记的占位模型继续推进，不要凭空宣布硬件已经适配。


一、资料优先级与本轮范围

1. 本提示词中的明确要求，高于参考图片。

2. 随附的最新整机图与爆炸图，只作外观、配色和拆分思路参考。
   图中的电机形状、内部连接、摆放位置和尺寸文字均未完成工程验证，
   不要直接照抄为加工依据。

3. 没有找到参考图片时，按本提示词继续建模，并注明未进行图片对照。

4. 本轮完成：
   - 参数化整机模型。
   - 零件拆分。
   - 内部空间布局与连接结构预研。
   - 真实模型渲染。
   - 几何与运动间隙检查。
   - 可确认部分的候选打印件导出。

5. 本轮不开发手机 App、云服务、语音 AI、完整运动固件，
   不设计定制 PCB，也不把动画当作自平衡验证。


二、不可擅自改变的外观

整体必须是：

“球形头 + 较大的球形身体 + 左右两个轮子”。

最重要的外观要求是简洁。

【头部】

- 以正球体为几何母体。
- 禁止非等比拉伸成椭球、鸡蛋形或圆角方盒。
- 正面为圆形黑色脸部显示窗。
- 必要的屏幕开窗和隐藏安装孔是局部例外，
  其余外表面必须保持同一球面。
- 圆脸中只显示两个简单的白色或淡蓝白色眼睛。
- 不增加嘴、鼻子或其他面部装饰。
- 区分保护片、黑色遮光边框、实际屏幕、PCB 和连接器。
  不能把显示模块画成没有厚度的黑色贴片。
- 头部绕竖直轴左右转动，初始范围 ±60°，参数可调。
- 不要外露脖子。
- 承重、旋转、固定和走线结构隐藏在头底部及身体顶部内部。
- 允许必要的细小运动间隙，不允许为了“无缝”而让零件穿模。

【身体】

- 同样以正球体为几何母体，母球直径大于头部母球直径。
- 只在顶部头部连接位置、左右车轮位置进行必要截切和开孔。
- 顶部形成截平安装区域，中央预留头部下缘及旋转机构所需开口。
- 不能让两个实体互相穿插来伪装头身连接。
- 左右优先采用对称、近竖直的平面截切，
  形成明确的车轮让位面。
- 不是用完整球体包裹、夹住轮胎，也不是把轮子直接塞进球体。
- 未截切区域保持原球面。
- 不用随意雕刻、整体压扁或拉长身体来修正比例。
- 腹部保留球面，不切平腹部来偷取离地间隙。
- 检查截切后的正面比例，不能切得太深，
  导致身体视觉上又明显小于头部。

【轮子与表面】

- 只有左右两个驱动轮。
- 无第三轮、后支撑轮、隐藏万向球、滑块或运行时接地支撑点。
- 轮子适度内收，但必须与身体保持真实可测的间隙。
- 不能贴住、穿模或靠阴影假装分离。
- 轮毂为机身同色的简洁圆盖。
- 轮胎为深灰或黑色。
- 不要黄色条、轮毂图案、装饰性轮眉或外露长轴。
- 不要鸭嘴、翅膀、尾巴、耳朵、天线、手臂。
- 腹部必须明显离地，不能再次出现“肚子贴地”的模型。
- 主体哑光暖白，圆形黑脸，简洁眼睛。
- 外壳不添加品牌文字和大面积装饰。
- 分件缝和必要紧固件可保留，但尽量放在背面、
  内侧或自然分界处，不为追求无缝而牺牲可拆装性。


三、参数化尺寸与几何关系

所有尺寸集中保存在 params.json，使用毫米语义。

以下是布局起点，不是最终加工尺寸，也不是已采购器件参数：

head_diameter_mm = 100
body_diameter_mm = 140
wheel_diameter_mm = 95
wheel_width_mm = 18

ground_clearance_mm = 20
# 目标可调范围：20～25 mm

wheel_body_gap_mm = 4
# 初始几何验收不得小于 3 mm

shell_thickness_mm = 2.4

assembly_clearance_per_side_mm = 0.3
# 仅为试打起点，后续按打印机、材料和配合方式校正

head_yaw_limit_deg = 60

同时参数化：
- 身体顶部截切深度。
- 左右截切位置。
- 头部嵌入深度。
- 头身运动间隙。
- 轮轴位置、轮距。
- 屏幕模块包络。
- 电机、轴径、轴承及安装接口。

坐标约定：
- Z 向上。
- X 为左右轮轴方向。
- Y 为前后方向。
- 地面为 Z=0。
- 明确记录正面对应 +Y 还是 -Y。

必须通过几何推导定位，不能分别拖动身体与轮子凑效果：

轮轴高度 = 轮胎半径

身体球心高度 = 身体母球半径 + 腹部离地间隙

轮轴相对身体球心的下移量
= 身体球心高度 - 轮轴高度

左右轮内侧面位置
由身体侧面截切位置和轮壳间隙推导。

以上初值中：
- 身体球心高度为 90 mm。
- 轮轴高度为 47.5 mm。
- 轮轴比身体球心低 42.5 mm。

这只验证外部几何关系，不代表电机已能装入。

整机总宽、总高从实际模型计算，不照抄参考图中的
“18 cm”等未经核对的文字。

先检查侧面截切后的身体比例，再检查轮轴是否位于
可安装的结构区域，以及电机、轴承、支架是否有空间。

初值存在冲突时，优先调整内部布局、截切深度和局部支架。
必要时可以调整建议尺寸，但必须保持球形与视觉比例，
并记录修改前后的数值和原因。

禁止通过减小必要间隙、把硬件缩小到虚假尺寸、
让支架穿壳、偷偷增加支撑轮来解决冲突。


四、三电机结构与自平衡前提

全机只使用三个执行器：

1. 左侧带编码器的驱动减速电机。
2. 右侧带编码器的驱动减速电机。
3. 一个头部左右转动的位置舵机或带位置反馈的执行器。

纯两轮版本按主动自平衡方案预留：
- IMU。
- 主控。
- 电机驱动。
- 电源模块。
- 编码器线路。

自平衡使用现有两台轮电机，不额外增加平衡电机。

不能因为模型能摆成直立姿态，就声称实物能自行站稳。
没有完成质量、重心、执行器能力和控制验证之前，
不承诺断电自立、稳定行驶或摔倒自起。

结构要求：

- 头部尽量轻。
- 电池位置可调整，便于后续验证重心。
- 电机和轮轴载荷通过内部承重框架传递。
- 不默认薄壳或未经核算的悬臂电机轴能承受全部载荷。
- 头部采用独立承重的转盘或轴承结构。
- 头部执行器负责驱动，不把整个头仅挂在舵机输出轴上。
- 头部走线预留弯曲空间、应力释放和转动限位。
- 不假设头部可以无限旋转。
- IMU 固定在刚性机身上，记录轴向，
  不能放在旋转头部或松动盖板上。
- 预留与电池串数匹配的保护、充电和稳压模块。
- USB-C 只是外部接口，不能默认任意电池组都可以直接充电。

已有真实器件资料时，优先采用并记录来源。
没有资料时，使用标注为 PLACEHOLDER / 待选型的包络模型。

不得编造已确认的电机型号、孔距、扭矩、质量或供电能力。


五、零件拆分与可装配性

建立真实独立部件，不要把所有东西合并成一个网格。

至少包含：

【头部组件】
- 头部前壳。
- 头部后壳。
- 屏幕固定框。
- 屏幕、保护片及相关电子件参考模型。
- 头部转盘。
- 轴承或承重环。
- 执行器支架及内部连接件。

【身体组件】
- 身体上壳。
- 身体下壳。
- 组装后恢复同一个截切球体外形。
- 内部承重框架。
- 左右电机安装件。
- 必要的轮轴支撑件。

【车轮组件】
- 左右轮毂。
- 左右轮胎。
- 左右简洁轮毂盖。

【内部安装组件】
- 可调电池托架。
- 主控和驱动板支架。
- IMU 安装位置。
- 电源开关、充电接口安装位置。
- 必要走线通道与紧固件。

PRINTABLE
PURCHASED_REFERENCE
PLACEHOLDER

电机、屏幕、轴承、电池、PCB 不作为普通打印件输出。

轮胎单独标明采购或柔性材料方案，
不默认使用硬质外壳材料打印。

为结构设计定位、固定、拆卸和工具操作空间。
可以使用螺钉与嵌件，但孔位与尺寸必须依据实际选型，
或者明确标记为待验证假设。

必须检查：
- 电机能否装入。
- 螺丝是否能拧到。

- 是否存在“只有把大零件穿过小孔才能装配”的问题。


六、Blender 项目与交付结构

使用脚本生成和更新模型，保留参数与构造基准。

- 脚本可重复执行，不重复堆积物体。
- 只清理本项目拥有的对象。
- 明确毫米参数与 Blender 内部单位的换算。
- 根据实际 Blender 版本使用兼容 API。
- 实体截切、开孔、加厚必须生成真实几何，
  不用透明材质或贴图代替。
- 装配图、爆炸图、各视图引用同一套零件几何。
- 禁止针对不同相机单独修改模型比例。
- 分开管理打印件、采购参考、占位件、标注、
  相机灯光和构造基准。
- 为头部绕 Z 轴、车轮绕 X 轴设置正确旋转中心。
- 装配姿态和爆炸姿态可以可靠切换。
- 爆炸位移与装配坐标分开保存，不能误导出爆炸坐标。

七、必须实际执行的检查

【几何与运动间隙】

- 检查头与身体的原始母球为正球。
- 对未截切、未倒角区域检查球面一致性，
  报告网格近似误差。
- 输出实际母球直径、截切后宽度、轮径、轮距、
  整机尺寸、轮轴高度和腹部离地间隙。
- 验证只有两个轮胎接地，其他整机部件不穿地。
- 测量轮胎及轮毂与静止外壳的实际最小间隙。
- 不能只凭截图或包围盒判断是否干涉。
- 检查车轮完整旋转一周是否碰撞。
- 检查头部在 ±60° 内转动是否碰撞。
- 写明检查方法、步长和覆盖范围。
- 检查机身绕轮轴前后倾斜 ±15° 时的最低点，
  报告接地风险。
- 倾斜检查只是几何运动包络检查，
  不代表已经验证安全运动范围或自平衡能力。
- 轴承接触面等预期接触应单独列出，
  不能误判，也不能随意忽略真正干涉。

【打印与装配】

- 在实际导出几何上检查闭合性、非流形边、
  法线、退化面、自交风险和壁厚。
- 检查螺柱、支架、配合缝与硬件包络是否干涉。
- 检查嵌件及螺丝刀操作空间。
- 报告尚未确认的器件安装接口。
- 分别导出候选打印件 STL，重新读取并比较尺寸和数量，
  避免 1000 倍缩放错误。
- 为配合孔、嵌件孔和卡接结构安排小样试打。
- 不宣称初始 0.3 mm 单边间隙适合所有打印机。

八、执行顺序和最终交付

按以下顺序推进：

外形与间隙
→ 内部布局
→ 分件与连接
→ 渲染与检查
→ 导出

先解决轮壳间隙和腹部离地，再做材质细节。
不要把时间花在广告海报排版上。

最终交付：

1. 可编辑装配 .blend，包含可切换爆炸状态。
2. 参数、建模、检查、渲染和导出脚本。
3. 实际执行命令与运行说明。
4. 正、侧、后、俯、仰正交视图。
5. 45° 效果图、爆炸图、内部布局或剖视图。
6. 一张能清楚量读腹部离地和轮壳间隙的工程检查图。
7. 部件清单：名称、数量、材料或类别、确认状态。
8. 已完成且适合候选试打的分件 STL。
9. 几何检查报告、未解决问题、打印方向建议。
10. 后续硬件适配与实物验证清单。

所有渲染必须来自实际 .blend 模型。
采用干净背景与简单照明，文字只标部件名称和实际尺寸。
不要广告文案、品牌故事或概念海报图标。

最终回复明确区分：
- 已生成。
- 已运行检查。
- 待选型适配。
- 待切片与试打。
- 待实物自平衡验证。

环境不能运行 Blender 时，仍交付可运行脚本并报告阻塞；
但不能声称已经生成 .blend、完成渲染或通过检查。

现在先检查工作目录和 Blender 环境，
建立参数与几何基准，然后直接开始制作。
