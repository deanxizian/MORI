# 原生通孔内层铜环恢复：搜索与审计模型核对

2026-10-26，开发基线仍为 R131G，PCB SHA256 `6f9d92ebf5a36598421f064cf29523081d8004d28d2e60ef7a0c36ff8b9bd099`。这里没有采用新的 PCB；所有行为探针均为本机独立副本，保留于 `robot/.state/c3-completion/trials/`。

原搜索器只使用已闪现铜环的连通区，因此可能漏掉通孔在未使用内层上的接线端点。KiCad 10.0.7 原生探针确认：J102.22 接入 In3 时，原有 1.7 mm 铜环会恢复；1.02 mm 钻孔和焊盘定义不变，In1/In2/In4 仍不闪现。恢复形状面积 2.273048401 mm²，与源焊盘原生潜在形状完全相等。见 [native-behavior.json](native-behavior.json)。

`R133PTH2` 用一段仍在焊盘范围内的短线验证行为，原生 **32 未连接 / 0 其他 DRC / 0 图板差异 / 0 启用 ERC**。这段线没有开发用途，也没有纳入开发稿。第一版较长探针碰到 IMU_SCL 间距并产生悬空线端，原始失败结果在 `initial_probe/`，未覆盖。

工具现在将此类端点标为“待原生恢复”，只支持明确的圆形金属化通孔；新线必须接到精确焊盘中心，完整潜在铜环先检查邻近已有铜间距。In2 仍受原 R13 精确白名单限制，不允许在 In1/In4 新增线。搜索不会把潜在铜环写入源铜模型，原生填铜后仍必须检查供电和参考地变化。

计划差异审查新增显式 `activate_pth_layers`：核对 UUID、针名、层、位置、源未闪现状态和实际新增线端点，逐层检查原生焊盘定义，拒绝借此修改 padstack、孔或位置。新增通孔参考面切换另按已有 2 mm 项目筛查检查；该阈值及未检查的外部模块回流均不能成为 EMC 资格。原始严格几何审计仍报告铜形状变化的 FAIL，不被改写。

[模型核对](model-validation.json) 通过：

- 原生探针的明确恢复计划通过 2493 项核对。
- 未声明恢复、SMD、非金属孔、禁止层四类反例均被拒绝。
- R131G 原计划复核通过 2503 项（新增两项空激活列表检查）；冻结的原始 2501 项报告不变。
- LINK_RX 可发现 J102.22 的 In3 端点，In2 未获许可，源文件和源闪现状态未被修改。

实际原生命令在 [commands.json](commands.json)、[refill-command.json](refill-command.json)；当时执行的本机验证脚本和输出在 [recorded_validation.py](recorded_validation.py)、[model-validation.log](model-validation.log)。脚本以 R131G 源快照及已构建的探针目录为输入，历史绝对路径不代表另一台机器已具备这些目录。

更新后进行的 40 组有界搜索给出两项提案，均未采用，见 `bounded_search/decisions.json`：FAULT_N 重复已知有问题的换层位置，HEAD_6V_RAW 到电容组则绕行约 42.1 mm、使用三个孔。不存在“搜索器已补齐便证明板子可布通/已验证”的结论。当前仍 32 未连接、六项历史回流提示，整板和实物资格未完成。
